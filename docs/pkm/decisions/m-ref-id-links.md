# M-Ref: ссылки как метаобъекты (id-референсы)

Статус: принято владельцем продукта, реализовано.

## Мотивация

Задача и ссылка концептуально одинаковы: объект с собственной жизнью + ярлык-референс в тексте. До M-Ref задача уже была таковой (`^task-<id>`), а ссылка держалась за строку заголовка (`[[Заголовок]]`) и ломалась при переименовании цели.

## Модель

- Инструментальные вставки («+ Заметка», «Привязать», автокомплит) пишут id-форму: `[[Заголовок ^n:<note-id>]]`. Канон — id; заголовок в скобках — кэш отображения.
- Рукописный `[[Заголовок]]` остаётся валидным: резолв по заголовку, frontier-семантика без изменений (низкий порог входа).
- В редакторе id-хвост и скобки скрыты декорацией (как `^task-id`); раскрытие сырого текста — только когда курсор строго внутри ссылки.
- `note_links.raw_target` для id-формы нормализуется в `n:<id>` (уникальность ребра не зависит от отображаемого заголовка). Миграции схемы не потребовалось.
- Explicit wiki-ссылка (любой формы) подавляет suggested-строку на ту же цель.

## Переименование (паттерн v3 §8.5)

Заголовки ярлыков обновляются лениво: при открытии заметки `refreshNoteLinkTitles` переписывает устаревшие display-заголовки id-ссылок (с `note_revision(reason='refresh-link-titles')` перед rewrite, INV-3). Ссылки title-формы и ссылки на удалённые заметки не трогаются.

## UX ярлыка ссылки

- Тап — переход к заметке (по id; fallback на заголовок, если цель удалена; frontier — предложение создать).
- Удержание / правый клик — меню: «Открыть», «Отвязать» (ярлык становится обычным текстом, объект живёт).

## Отложено

- «Закрепить» рукописную title-ссылку в id-форму явным действием из меню.
- «Переименовать» цель из меню ярлыка.
- Вычистка `^n:`-якорей при экспорте markdown (M1.5c).
